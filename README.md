# Snake RL

ระบบเรียนรู้แบบเสริมกำลัง (Reinforcement Learning) ที่ฝึกให้ตัวแทน (agent) เล่นเกมงูได้ด้วยตนเอง
พัฒนาด้วย Deep Q-Network (DQN) บน PyTorch และแสดงผลเกมด้วย Pygame

โมเดลในที่เก็บนี้ผ่านการฝึกมาแล้ว **25,000 เกม** สถิติสูงสุด **89 คะแนน** คะแนนเฉลี่ยสะสม **33.50**

## คุณสมบัติ

- **Deep Q-Network** — โครงข่ายประสาทเทียมแบบ 2 ชั้น เรียนรู้จากประสบการณ์ผ่าน Experience Replay
- **ระบบ Checkpoint ที่ปลอดภัย** — บันทึกด้วยรูปแบบ temp → fsync → atomic replace พร้อมไฟล์สำรอง `.bak`
  ทำให้การขัดจังหวะระหว่างบันทึกไม่ทำให้ข้อมูลเสียหาย
- **ฝึกต่อจากจุดเดิมได้** — กู้คืนทั้งน้ำหนักโมเดล, สถานะ optimizer, replay memory และประวัติสถิติ
- **กำหนดเป้าหมายการฝึกได้** — หยุดฝึกอัตโนมัติเมื่อถึงจำนวนเกมที่กำหนด พร้อมบันทึกผลครบถ้วน
- **โหมดสาธิต** — สคริปต์แยกสำหรับชมโมเดลเล่นโดยไม่แก้ไขข้อมูลการฝึก
- **ส่วนติดต่อผู้ใช้ธีมมืด** — พื้นหลังไล่เฉดเข้ม เส้นตาราง งูมุมมน พร้อมดวงตาที่หันตามทิศทางการเคลื่อนที่
- **กราฟติดตามผลแบบสด** — แสดงคะแนนรายเกมและคะแนนเฉลี่ยสะสมระหว่างฝึก


```bash
python -m venv .venv
```

Windows (Command Prompt):

Windows (Git Bash):
```bash
source .venv/Scripts/activate
```

macOS / Linux:
```bash
source .venv/bin/activate
```

เมื่อเปิดใช้งานสำเร็จ จะปรากฏ `(.venv)` อยู่หน้าบรรทัดคำสั่ง

เหมาะสำหรับผู้ที่ใช้ Anaconda หรือ Miniconda อยู่แล้ว และต้องการให้ระบบจัดการเวอร์ชัน Python ให้ด้วย

```bash
conda create -n snake-rl python=3.12
```

### play.py — ชมโมเดลเล่นเกม

สคริปต์สำหรับสาธิตผลการฝึก โหลดโมเดลที่ฝึกไว้แล้วมาเล่นให้ชม
**ไม่มีการฝึกและไม่มีการเขียนทับไฟล์ใด ๆ** จึงปลอดภัยต่อข้อมูลการฝึก

```bash
python play.py
```

#### ตัวเลือกบรรทัดคำสั่ง

| ตัวเลือก | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `--games N` | `5` | เล่น N เกมแล้วหยุด ใส่ `0` เพื่อเล่นวนไม่สิ้นสุด |
| `--speed N` | `20` | ความเร็วในการแสดงผล หน่วยเป็นเฟรมต่อวินาที |
| `--epsilon F` | `0.0` | สัดส่วนการสุ่มเดิน (0.0–1.0) ใช้แก้ปัญหางูเดินวนซ้ำที่เดิม |
| `--weights PATH` | อัตโนมัติ | ระบุไฟล์โมเดลเอง |

#### ตัวอย่างการใช้งาน

```bash
python play.py --games 0                          # เล่นวนไม่สิ้นสุด
python play.py --speed 60                         # แสดงผลเร็วขึ้น
python play.py --games 10 --speed 15              # เล่น 10 เกมแบบช้า ๆ
python play.py --epsilon 0.02                     # เพิ่มการสุ่มเล็กน้อย
python play.py --weights model/model_final.pth    # ระบุไฟล์โมเดลเอง
```

#### การควบคุมระหว่างเล่น

| ปุ่ม | การทำงาน |
|---|---|
| `SPACE` | หยุดชั่วคราว / เล่นต่อ |
| `ESC` | ออกจากโปรแกรม |
| ปิดหน้าต่าง | ออกจากโปรแกรม |

#### ลำดับการค้นหาไฟล์โมเดล

เมื่อไม่ระบุ `--weights` สคริปต์จะค้นหาตามลำดับดังนี้ และใช้ไฟล์แรกที่โหลดสำเร็จ

1. `model/checkpoint.pth`
2. `model/checkpoint.pth.bak`
3. `model/model_final.pth`
4. `model/model.pth`

#### ข้อมูลที่แสดงบนหน้าจอ

- **มุมบนซ้าย** — คะแนนของเกมปัจจุบัน และสถิติของรอบการเล่นนี้ (คะแนนสูงสุด / คะแนนเฉลี่ย / จำนวนเกม)
- **มุมล่างซ้าย** — ชื่อไฟล์โมเดลที่โหลด จำนวนเกมที่ผ่านการฝึก และสถิติสูงสุดจากการฝึก

> **หมายเหตุ** — ไฟล์ `model_final.pth` และ `model.pth` บรรจุเฉพาะน้ำหนักโมเดล ไม่มีข้อมูลประวัติการฝึก
> เมื่อโหลดไฟล์เหล่านี้ แถบด้านล่างจะแสดงจำนวนเกมและสถิติเป็น `0` ซึ่งไม่กระทบต่อฝีมือการเล่น

### agent.py — ฝึกโมเดล

สคริปต์หลักสำหรับฝึกตัวแทน

```bash
python agent.py
```

#### ตัวเลือกบรรทัดคำสั่ง

| ตัวเลือก | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `--resume` | ปิด | ฝึกต่อจาก checkpoint เดิม หากไม่ระบุจะเริ่มใหม่จากศูนย์ |
| `--games N` | `25000` | หยุดฝึกเมื่อถึงเกมที่ N ใส่ `0` เพื่อฝึกไม่จำกัด |

#### ตัวอย่างการใช้งาน

```bash
python agent.py --resume                # ฝึกต่อจนครบ 25,000 เกม
python agent.py --resume --games 30000  # ขยายเป้าหมายเป็น 30,000 เกม
python agent.py --resume --games 0      # ฝึกต่อโดยไม่จำกัดจำนวนเกม
python agent.py --games 5000            # เริ่มฝึกใหม่จากศูนย์ หยุดที่ 5,000 เกม
```

> **คำเตือน** — การรัน `python agent.py` โดยไม่ใส่ `--resume` จะเริ่มฝึกจากศูนย์
> และเขียนทับ `model/checkpoint.pth` ที่มีอยู่ หากต้องการเก็บโมเดลเดิมไว้
> ให้สำรองโฟลเดอร์ `model/` ก่อนเสมอ

#### พฤติกรรมเมื่อถึงเป้าหมาย

เมื่อจำนวนเกมถึงค่าที่กำหนด ระบบจะบันทึกข้อมูลทั้งหมดให้เสร็จสิ้นก่อน จากนั้นจึงหยุดและแสดงสรุปผล

```
Reached 25000 games. Training stopped.
  record     : 89
  mean score : 33.50
  checkpoint : model\checkpoint.pth
  weights    : model/model_final.pth
```

หากรันซ้ำโดยที่จำนวนเกมถึงเป้าหมายแล้ว ระบบจะไม่ฝึกต่อและแจ้งว่า

```
Already at 25000 games (target 25000). Nothing to train.
```

#### การบันทึกระหว่างฝึก

ระบบบันทึกข้อมูลทุกครั้งที่จบเกม ประกอบด้วย checkpoint, ไฟล์สถิติ และภาพกราฟ
จึงสามารถหยุดด้วย `Ctrl+C` ได้ทุกเมื่อ แล้วฝึกต่อด้วย `--resume` โดยไม่สูญเสียความคืบหน้า

## ไฟล์ที่ระบบสร้างขึ้น

ไฟล์ทั้งหมดในโฟลเดอร์ `model/` ถูกสร้างโดยกระบวนการฝึก

| ไฟล์ | คำอธิบาย |
|---|---|
| `checkpoint.pth` | สถานะการฝึกฉบับสมบูรณ์ — น้ำหนักโมเดล, optimizer, replay memory และประวัติสถิติ |
| `checkpoint.pth.bak` | สำเนาสำรองของ checkpoint รอบก่อนหน้า ใช้กู้คืนเมื่อไฟล์หลักเสียหาย |
| `model_final.pth` | น้ำหนักโมเดลเมื่อการฝึกถึงเป้าหมาย มีขนาดเล็กเพราะไม่มี replay memory |
| `model.pth` | น้ำหนักโมเดลที่ทำสถิติสูงสุด บันทึกทุกครั้งที่ทำลายสถิติเดิม |
| `training_stats.json` | คะแนนรายเกมและคะแนนเฉลี่ยสะสมทั้งหมด |
| `training_plot.png` | กราฟแสดงความคืบหน้าของการฝึก |

## รายละเอียดทางเทคนิค

### โครงสร้างโครงข่าย

```
อินพุต (11) → Linear → ReLU → ชั้นซ่อน (256) → Linear → เอาต์พุต (3)
```

### เวกเตอร์สถานะ (11 มิติ)

| ดัชนี | ความหมาย |
|---|---|
| 0–2 | มีอันตรายอยู่ด้านหน้า / ด้านขวา / ด้านซ้ายหรือไม่ |
| 3–6 | ทิศทางที่งูกำลังเคลื่อนที่ (ซ้าย, ขวา, บน, ล่าง) |
| 7–10 | ตำแหน่งอาหารเทียบกับหัวงู (ซ้าย, ขวา, บน, ล่าง) |

### พื้นที่การกระทำ (3 ทางเลือก)

| เวกเตอร์ | ความหมาย |
|---|---|
| `[1, 0, 0]` | เดินตรงไปตามทิศทางเดิม |
| `[0, 1, 0]` | เลี้ยวขวา (หมุนตามเข็มนาฬิกา) |
| `[0, 0, 1]` | เลี้ยวซ้าย (หมุนทวนเข็มนาฬิกา) |

### โครงสร้างรางวัล

| เหตุการณ์ | รางวัล |
|---|---|
| กินอาหาร | `+10` |
| ชนกำแพง ชนตัวเอง หรือเดินวนเกินกำหนด | `−10` |
| การเคลื่อนที่ปกติ | `0` |

### ค่าพารามิเตอร์หลัก

| พารามิเตอร์ | ค่า | คำอธิบาย |
|---|---|---|
| `MAX_MEMORY` | 100,000 | ความจุสูงสุดของ replay memory |
| `BATCH_SIZE` | 1,000 | จำนวนตัวอย่างต่อรอบการฝึกแบบ long memory |
| `LR` | 0.001 | อัตราการเรียนรู้ของ Adam optimizer |
| `gamma` | 0.9 | ค่าลดทอนรางวัลในอนาคต |
| `epsilon` | `80 − n_games` | ค่าควบคุมการสำรวจ ลดลงตามจำนวนเกมที่ผ่านไป |

### สมการที่ใช้ปรับค่า

การฝึกใช้สมการ Bellman ในรูปแบบ Q-learning

```
Q(s, a) ← r + γ · max Q(s′, a′)
```

โดยคำนวณค่าคลาดเคลื่อนด้วย Mean Squared Error แล้วปรับน้ำหนักผ่าน backpropagation


### หน้าต่างเกมไม่ปรากฏ หรือโปรแกรมหยุดทำงานทันที

Pygame ต้องการระบบแสดงผล หากรันบนเซิร์ฟเวอร์ที่ไม่มีจอภาพจะเกิดข้อผิดพลาด

### เกมแสดงผลช้าเกินไปหรือเร็วเกินไป

- **โหมดสาธิต** — ปรับด้วย `--speed` เช่น `python play.py --speed 60`
- **โหมดฝึก** — แก้ค่าคงที่ `SPEED` ในไฟล์ `game.py` ค่ายิ่งสูงยิ่งฝึกเร็ว

### งูเดินวนซ้ำที่เดิมไม่ยอมกินอาหาร

เป็นข้อจำกัดของเวกเตอร์สถานะที่มองเห็นเฉพาะช่องที่ติดกับหัวงู
แก้ปัญหาเฉพาะหน้าได้ด้วยการเพิ่มการสุ่มเล็กน้อย

```bash
python play.py --epsilon 0.02
```

### RuntimeError: No valid checkpoint could be loaded

ไฟล์ checkpoint เสียหายและไม่มีไฟล์สำรองที่ใช้ได้
หากยังมี `model/model.pth` ระบบจะพยายามกู้คืนน้ำหนักโมเดลให้โดยอัตโนมัติ
แต่สถานะ optimizer และ replay memory จะเริ่มต้นใหม่

### ไม่แน่ใจว่าโมเดลฝึกไปถึงเกมที่เท่าไร

```bash
python -c "import torch; c = torch.load('model/checkpoint.pth', map_location='cpu', weights_only=False); print('games:', c['n_games'], '| record:', c['record'])"
```

## หมายเหตุด้านความปลอดภัย

การโหลด checkpoint ใช้พารามิเตอร์ `weights_only=False` เนื่องจากไฟล์บรรจุ replay memory
ที่เป็นอ็อบเจกต์ NumPy ซึ่งต้องอาศัยการ deserialize แบบเต็มรูปแบบ
ไฟล์เหล่านี้ถูกสร้างขึ้นภายในโปรเจกต์เอง **ไม่ควรโหลดไฟล์ checkpoint จากแหล่งที่ไม่น่าเชื่อถือ**
